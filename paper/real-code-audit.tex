\section{Public-Code Mutation-Shape Stress Test}
\label{sec:real-code-audit}

The internally authored authority cases establish controlled Patch behavior, but they do not answer a narrower external-plausibility question: do state updates in mature public software exhibit mutation shapes that the current Patch \texttt{Change} abstraction is designed to represent? We therefore inspect 15 commit-bound mutation sites from Excalidraw, VS Code, and JupyterLab. This is \emph{not} an integration test. None of these projects is translated to, ported to, or executed by Patch.

The connection to Patch is deliberately specific. For each public mutation site, we ask two questions: (1) can the observed state transition be described as one current Patch-style semantic Change over one logical persistent target using a set/add/remove interpretation, and (2) would Patch own the actual commit route, or is persistence controlled by a foreign host API? A site can therefore resemble a Patch Change semantically without constituting Patch support.

\paragraph{Method.}
The corpus freezes exact repository commits, paths, and textual anchors in \texttt{evaluation/real-code-audit/corpus.csv}. The projects provide three distinct state contexts: application-owned editor state, collection mutation, and host-backed persistent state. Candidate files were located with state-specific searches and frozen before classification. Each site is classified independently along two dimensions: semantic shape and commit-route ownership. A \emph{single-target} site has a set/add/remove interpretation over one logical state target. A \emph{multi-target bundle} changes several related fields in one source update. \emph{Application-owned} state is ordinary application/editor state; \emph{host-backed} state is committed by an external service such as VS Code Memento or JupyterLab \texttt{IStateDB}.

We count host-backed updates conservatively. A one-key Memento update, for example, has a compact set-like state-transition shape, but Patch does not own the Memento commit route and Paper~1 does not claim a certified adapter. Likewise, multi-field source updates are not silently decomposed and counted as supported. If atomic grouping matters, that requires machinery outside this paper.

\paragraph{Observations.}
Twelve of the fifteen inspected sites have a single-target shape: ten are set-like, one adds to a collection, and one removes from a collection. This count is \emph{not} a Patch coverage result. It answers only a representational question for the frozen examples: the basic semantic-delta shapes used by Paper~1 also occur outside the paper's synthetic numeric programs.

The stress test simultaneously exposes two limits. First, seven sites use host-backed persistence. Their state-transition meaning may be compact, but Patch is not the commit authority unless a future adapter brings that host state under the semantic Change route. Second, three Excalidraw updates bundle related fields in one source-level state update. Paper~1 can describe the member transitions individually, but it does not claim atomic multi-target grouping or relational invariant preservation.

The useful distinction is therefore \emph{representational fit versus commit-route ownership}. For example, VS Code's \texttt{globalState.update(key, true)} has a set-like transition that resembles a Patch \texttt{change} with \texttt{set true}; nevertheless VS Code Memento, not Patch, commits that persistent update. Conversely, a multi-field Excalidraw \texttt{setState} exposes a mutation shape that the current single-target Change model does not claim to commit atomically. These are stress cases for Patch's architectural boundary, not demonstrations that the projects run on Patch.

\paragraph{Validity boundary.}
This is purposeful diversity sampling, not random sampling, and 15 sites cannot estimate ecosystem prevalence. Neither source compatibility nor porting feasibility is measured. The stress test does not execute third-party code through Patch, measure migration effort, establish usability, certify foreign state adapters, or extend the beta~32 Lean fragment. Its role is narrower: to test whether the current Patch mutation abstraction has recognizable public-code analogues and to expose cases where that abstraction or its ownership boundary stops. The complete manifest and classification rationale are part of the repository artifact.
