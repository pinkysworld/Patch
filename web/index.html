Semantic security

Permission to change is more precise than permission to write

A normal write permission says code may modify a value. Patch can say that a recipe may only perform a particular semantic change, for example player.score may increase up to 10. A replacement with set score = 999 is a different semantic operation and is rejected.

With bonus number 0..10, the compiler can prove many dynamic bounded changes instead of rejecting them just because the amount is a variable.

Compiler ↔ formal model

Beta 5 makes formal coverage inspectable

The compiler now independently reconstructs a Lean-like control-flow signature from the real Patch AST for the currently supported subset and compares it with the production Change Signature. A supported mismatch is a compiler error.

Unsupported constructs are listed explicitly rather than silently receiving a verification claim. Run patch formal program.patch to see which entries currently sit inside the validation boundary.

Causal provenance

Ask Patch why a value or condition exists

why score explains the recorded semantic changes behind the current value. why score > 100 replays history and identifies the first recorded transition that made the condition true when one can be isolated.

GUI-driven changes can retain provenance such as event bonus clicked → recipe reward → change score.

Formal verification

The central contract chain is machine checked for a formal core

The formal/ project proves State-Change Factorization, Mutation Transparency and interval-containment composition. It also proves that every runtime semantic effect of a structured core execution is contained in its inferred Change Signature.

Lean composes that result with capability-policy admission, yielding RuntimeChanges ⊆ Signature ⊆ Capability. Beta 5 does not claim that JavaScript itself is formally verified; the new bridge is translation-validation evidence on the path toward that correspondence.

Research project

Patch: State-Change Factorization and Semantic Change Contracts

The research claim is intentionally narrower than “patches are new.” Patch investigates semantic change as the exclusive ordinary mutation mechanism of a low-complexity language. On top of that mandatory representation, the compiler derives semantic signatures, capability proofs, bounded range facts and provenance.

Current status: the formal core has machine-checked Change Signature Soundness and end-to-end policy containment. Beta 5 adds a reproducible production-to-formal validation boundary for a conservative subset. Full compiler correspondence or a verified checker remains the major formal objective.
