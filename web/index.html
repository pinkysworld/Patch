Patch programming language

Small syntax. Visible changes. One Studio.

Patch is an experimental language where existing persistent state changes through semantic change operations rather than ordinary reassignment. Run projects in the browser, inspect the Change Contract, and build Console or Window applications for Windows, macOS and Linux from the same source.

Build formats & important boundariesChoose the right artifact

Direct Wasm is real Wasm

The direct backend lowers the supported numeric subset to WebAssembly instructions. The raw .direct.wasm currently imports Patch's small host ABI, so it is not yet a standalone WASI command. Use patch run-wasm, a Standalone Web App, or a desktop package for a ready-to-run host.

Window packages are standalone

Current Window projects can be packaged as desktop GUI applications for all three supported desktop operating systems. They run the Patch Window model inside a generated desktop player; beta.17 does not claim native AppKit, Win32 or GTK widget lowering yet.

Research & verificationTechnical view

Research project

State-Change Factorization

The central claim is deliberately narrow: ordinary post-creation persistent mutation must execute through a semantic change. Patch does not claim that patches, undo, effects or first-class state change are individually new.

Change Capabilities constrain semantic operation and magnitude, for example allowing a recipe to increase a value only up to a declared bound.

Formal assurance

Lean-checked core

The formal project covers State-Change Factorization, Mutation Transparency, Change Signature Soundness, policy containment and integer range-analysis soundness for explicitly modeled fragments.

The Verified checker and Source core keep producer claims separate from Lean validation. patch certify emits Lean-checkable certificates for supported protected programs.

Runtime validationCompiler evidence, not overclaiming

Independent transition model

For the direct numeric backend, an independent validator reconstructs expected Change-IR transitions instead of using the Wasm lowerer or the production interpreter as its sole oracle.

Semantic effect checks

The validator reconstructs concrete increase/decrease/set/clear effects and checks them against static Change Signatures and protected Change Capabilities. This is translation/runtime validation evidence, not a theorem that the complete JavaScript compiler is verified.
