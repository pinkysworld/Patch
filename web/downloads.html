Offline IDE boundary

Stage 1 packages the generated public Studio module closure and serves it only over an ephemeral 127.0.0.1 endpoint with a random per-launch path, GET/HEAD-only routing, traversal rejection, restrictive CSP and integrity verification.

Stage 2 R0.1 is implemented in source. The versioned patch-offline-build-bridge/0.1 accepts only authenticated POST /v1/build requests for build-native-window. It uses a per-launch Bearer capability, closed JSON schema, canonical workspace/source containment, symlink checks and a fixed output root. It exposes no general shell, argv, environment or arbitrary output-path API.

The installed distributions do not yet expose host-native desktop Build as a completed user-facing workflow. Compiler/runtime packaging beside Studio, explicit workspace-open authority, capability delivery to the UI, visible Build wiring and installed-distribution native-build self-smokes remain. Use the separate offline compiler for host-native output today.

Current native boundary

The current desktop line is Native GUI IR 1.9 / payload v19 / runtime v1.10. Native GUI IR 1.8 / payload v18 / runtime v1.9 is the Button/ImageList underlay. Native GUI IR 1.7 / payload v17 / runtime v1.8 remains an explicit Offline Compiler compatibility line. Native GUI IR 1.6 / payload v16 / runtime v1.7 is the earlier PaintBox line, Native GUI IR 1.5 / payload v15 / runtime v1.6 the Shape line, Native GUI IR 1.4 / payload v14 / runtime v1.5 the Chrome line, Native GUI IR 1.3 / payload v13 / runtime v1.4 the Slider-capable historical line, and Native GUI IR 1.2 / payload v12 / runtime v1.3 the frozen TreeView line. Versioned contracts are not silently reinterpreted.

PictureBox note: current desktop Picture decoding supports bounded project-resource and data-URI PNG/JPEG images through Win32/WIC, AppKit/NSImage and GTK/GdkPixbuf under native-picture-formats/1.0. This is not a claim of complete portable image-source rendering across every project image type or display property. Native WebP/SVG remain deferred and fail closed.

Current native Window surface

Windows, macOS and Linux offline linking uses the same semantic GUI contract as Patch Studio's token-free Ready path. Toolkit interaction remains transient until Patch source performs an explicit change.

  • Slider: finite numeric changed value inside the declared range.
  • Table/Grid: selected row is a transient text-list event value.
  • Menu: separators, portable shortcuts and source-backed Boolean enabled/checked projections.
  • TreeView: selected root-to-node display path is a transient text-list event value.
  • Panel: Stage 1 native visual grouping; full child-container semantics remain a later contract.
  • Timer: native scheduling with Patch ticked events.
  • PictureBox: bounded PNG/JPEG decoding plus the current click path.
  • Shape: rectangle, rounded rectangle, ellipse and line through native renderers.
  • PaintBox: pure paint rendering including bounded PNG/JPEG draw image.
  • ImageList/Button images: named project resources flow through the IR1.8/BIMG layer and native Win32/AppKit/GTK Button consumers.
  • Window/application icons: payload v19/WICO drives native Form icons; Windows embeds the application icon in the PE slot, macOS packages .icns, and Linux emits hicolor + .desktop metadata.

How Patch Studio verifies Ready runtimes

The browser path has a separate integrity gate from the offline compiler. Pages requires studio-runtime-v0.6 plus the three native runtime-v1.10 releases, verifies the recorded release digests and publishes runtime-manifest.json. Patch Studio re-hashes the selected runtime with Web Crypto before sealing a Ready app.

Verify a download

Download SHA256SUMS from the same rolling channel and verify the exact bytes before first use or after replacing a rolling-beta download.

# Linux Offline Studio
sha256sum PatchStudio-linux-x64

# macOS Intel Offline Studio
shasum -a 256 PatchStudio-macos-x64.tar.gz

# Windows ARM64 Offline Studio
Get-FileHash .\PatchStudio-windows-arm64.exe -Algorithm SHA256

# Windows standalone compiler
Get-FileHash .\patch-windows-x64.exe -Algorithm SHA256

SHA-256 verifies release-byte consistency. It is not a replacement for Authenticode, Developer ID/notarization or an independent signing authority.

Platform notes

Windows

Offline Studio publishes self-contained x64 and ARM64 executables. The x64 offline compiler links Current Ready Window projects into native Win32 .exe output through runtime v1.10.

macOS Apple Silicon

Offline Studio publishes a self-contained Apple Silicon binary. Development builds are ad-hoc signed, not Developer ID notarized.

macOS Intel

Offline Studio publishes an embedded-runtime kit, PatchStudio-macos-x64.tar.gz. It includes its own Intel Node runtime. The compiler is also distributed as a portable tar.gz kit.

Linux

Offline Studio publishes x64 and ARM64 self-contained binaries. The x64 compiler embeds the GTK3 runtime v1.10 linker; resulting GUI executables require compatible normal GTK3/system libraries.

FreeBSD

The portable Node 18+ Offline Studio path is executed in a real FreeBSD 15 x64 VM. The separate compiler supports Console linking through portable C99 and requires local Node 22+ and cc. Native FreeBSD Window/GUI linking is not claimed yet.
