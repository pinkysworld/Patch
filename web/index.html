Programming should feel like making clear, inspectable changes.

Patch is an experimental general-purpose language where persistent state changes only through explicit semantic changes. Patch 0.2 beta.2 can also infer what kinds of changes a recipe may produce and optionally check them against a declared change capability policy.

  player.score may increase up to 10

make reward(player):

Semantic security

Permission to change is more precise than permission to write

A normal write permission says that code may modify a value. Patch can say that a recipe may only perform a particular semantic change, for example player.score may increase up to 10. A replacement with set score = 999 or a larger statically known increase is rejected at compile time.

The compiler is conservative: when a numeric bound cannot be proved from the current source, it rejects the bounded policy rather than guessing.

Research project

Patch: State-Change Factorization and Semantic Change Contracts

The research claim is intentionally narrower than “patches are new.” Patch investigates semantic change as the exclusive ordinary mutation mechanism of a low-complexity language. The new Change Signature/Capability layer asks a further question: if every mutation already has semantic structure, can the compiler infer the set of changes a component may produce and prove that those changes stay inside a semantic policy?

Current status: a credible high-venue research direction, not yet a finished high-venue result. Formalization, mechanization, systematic related-work analysis, direct compiled execution and measured evaluation remain required.
