Range soundness

For the verified integer fragment, inferred bounds are now a theorem

PatchRange.lean models integer literals, ranged variables, addition, subtraction, negation and multiplication by a non-negative integer constant. It defines both concrete evaluation and interval analysis.

The theorem rangeAnalysisSound proves that if the concrete environment respects the declared ranges, every concrete result lies inside the interval returned by formal analysis. Thus bonus: 0..5 with bonus * 2 is formally bounded by 0..10.

Conservative boundary

The verified range fragment is intentionally smaller than production arithmetic

The production analyzer can currently reason about more expressions. Beta 9 certification deliberately refuses decimal semantics, division and general multiplication unless they are later modeled and proved.

src/formal-range.js independently extracts a formal integer expression and compares its interval with the ordinary production analyzer result before a range claim enters a certificate.

Semantic security

Permission to change is more precise than permission to write

A normal write permission says code may modify a value. Patch can say that a recipe may only perform a particular semantic change, for example player.score may increase up to 10. A replacement with set score = 999 is a different semantic operation and is rejected.

For beta.9-certified integer expressions, quantitative bounds now have a machine-checked formal soundness result rather than only a production interval claim.

Source core

Lean sees source mutation verbs before semantic normalization

The certificate contains a proof-free SourceStmt whose changes still say add, remove, set or clear. PatchSource.lean validates raw range bounds and performs semantic direction normalization itself.

For example, source-level add -5 can be normalized by Lean to semantic decrease of 5. The separately emitted semantic evidence must match this Lean-computed lowering.

Verified evidence

Range, source, evidence and production signature remain separate claims

patch certify protected.patch can emit formal RangeExpr claims, a Source core, a separately produced EvidenceStmt, a separate production Change Signature claim, and the policy.

Lean checks formal interval analysis, source to evidence equality, evidence decoding, formal signature reconstruction, production-signature agreement and semantic policy containment.

Verified checker

The semantic policy decision remains machine checked

PatchChecker.lean proves that a successful executable policy check implies the relational policy judgment used by the formal semantics.

PatchSource.checkedSourceExecutionCannotEscape lifts this to executions admitted by the formal Source-core semantics.

Trust boundary

The remaining frontend and runtime gaps are explicit

JavaScript still parses full Patch source and extracts the formal RangeExpr and SourceStmt. Those extraction functions are independently implemented and cross-checked, but they are not yet machine-proved translations of the production parser.

The production runtime is also not yet formally proved to correspond to evalRangeExpr and SourceExecutes. Beta 9 does not claim full compiler verification.

Causal provenance

Ask Patch why a value or condition exists

why score explains recorded semantic changes behind the current value. why score > 100 replays history and identifies the first recorded transition that made the condition true when one can be isolated.

GUI-driven changes can retain provenance such as event bonus clicked → recipe reward → change score.

Formal verification

The proof chain includes formal quantitative reasoning

Lean proves State-Change Factorization, Mutation Transparency, Change Signature Soundness, RuntimeChanges ⊆ Signature ⊆ Capability, and range-analysis soundness for the supported integer expression fragment.

Formal CI explicitly builds PatchFormal, PatchSignature, PatchChecker, PatchEvidence, PatchSource and PatchRange, then compiles a certificate generated from production Patch source.

Research project

Patch: State-Change Factorization and Semantic Change Contracts

The research claim is intentionally narrower than “patches are new.” Patch investigates semantic change as the exclusive ordinary mutation mechanism of a low-complexity language. Operation- and magnitude-aware contracts are derived from that mandatory representation.

Current status: beta.9 adds machine-checked range-analysis soundness for a useful integer fragment and connects production expressions to it through an independent formal extractor and generated Lean obligations. The next critical obligations are stronger source/AST extraction correspondence and production runtime-to-formal execution correspondence, followed by measured security case studies.
