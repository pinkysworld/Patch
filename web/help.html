Build something without fighting the IDE.

Quick help for commands, editing, multi-file projects, visual form design, keyboard-only structural Properties, project recovery, verified Ready builds and local downloads.

Command Palette

Press Ctrl/Cmd+K or choose Commands in Studio. Type to filter, use Arrow Up/Down to move through results, press Enter to run the selected command, and Escape to close.

The current palette can Run, Build, focus the source editor, switch to Designer/App/Output/Changes/IR, open Recovery and navigate to Documentation, Downloads or Help. These entries delegate to the existing Studio actions. Palette search and selection are transient IDE state and do not modify Patch source or application state. The same search also lists project files and outline symbols, including Thing fields as player.score and recipe parameters as reward.bonus.

Source editor

The active file name stays in the editor title. As you type or click, the editor reports the current Ln and Col. That caret status is transient IDE state. It is not Patch application state, Change History or project persistence.

Design a Window app

1

Choose Window as the project type or open a Window example.

2

Use the Designer palette or categorized Add control picker to add Text, Button, Input, Checkbox, Radio, Combo, ListBox, Slider, Table, TreeView or Tabs controls. Slider exposes source-backed id/range/step Properties. Table, TreeView and Tabs expose source-backed structural editors in Properties.

3

Select a control to move it. Drag it to snap nearby edges and centers to visible alignment guides, hold Alt while dragging to bypass snapping, use the arrow keys for 1 px source-backed positioning, hold Shift for 10 px keyboard steps, or edit X/Y/W/H in Properties. Drag its resize grip to change its size.

4

Use Ctrl-click, Cmd-click or Shift-click to add or remove controls from the current selection. The solid control is the primary control. Drag or keyboard-move that primary control to move the selected group together. Alignment commands write the resulting positions back into Patch source.

5

The Properties panel is wider on desktop, can be resized by dragging its left separator, can be hidden with the Properties button and remembers its local width. On narrower screens it moves below the canvas. Properties never stores a second hidden form model.

6

Choose an Anchor or Dock policy in Properties when a control should react to Form resizing. Studio writes that policy visibly into source as a # @layout ... directive.

7

Resize the form itself from the lower-right grip. Forms may grow beyond the visible Designer width; use the Designer scrollbars to reach the rest. The same source-backed Anchor/Dock policy is honored by Standalone Web, direct native AOT, token-free Ready apps and supported offline-linked Window apps on Windows, macOS and Linux.

Slider Stage 1

Slider Stage 1 is source-backed in the Designer, Standalone Window Web and the current native desktop line. Its changed event exposes a finite numeric value inside the declared range. Moving the control does not implicitly persist application state.

create number volume = 50
window "Mixer":
  slider 0..100 as volume step 5
when volume changed:
  change volume:
    set = value

Current Native GUI IR 1.3 / payload v13 / runtime v1.4 implements Slider through Win32 TRACKBAR, AppKit NSSlider and GTK3 GtkScale. Native GUI IR 1.2 / payload v12 / runtime v1.3 is the frozen TreeView compatibility line and remains Slider fail-closed. Use the current Ready/offline path for native Slider applications.

Keyboard-only structural Properties

TreeView nodes and Tabs pages use roving keyboard focus: Arrow Up/Down selects the previous or next visible item, while Home/End jumps to the first or last visible item. Focus follows the selected item even when the source-backed editor re-renders. When a structure filter is active, hidden matches are excluded from keyboard navigation.

With a TreeView node focused, use Ctrl/Cmd + Arrow Up/Down to move it, Ctrl/Cmd + Arrow Left/Right to outdent or indent it, and Ctrl/Cmd + Enter to focus its label expression. The same hierarchy shortcuts work for a nested TreeView inside Tabs.

With a Tabs page focused, Ctrl/Cmd + Arrow Up/Down reorders the page and Ctrl/Cmd + Enter focuses its title expression. In Table cells/columns, TreeView labels and Tabs titles, Ctrl/Cmd + Enter performs the corresponding Apply or Rename action.

The filter field reports how many nodes/pages/controls remain visible and shows an explicit no-match state. An empty Table shows No rows yet with Add first row. These are IDE conveniences only: filtering never changes source, and the quick actions delegate to the existing source-backed structural editor actions.

Inside an expanded nested Table or TreeView structure editor, Escape closes the editor and restores focus to its Edit button. These focus/selection states are IDE-only and never become Patch application state or Change History.

Manual Narrator/VoiceOver/Orca verification remains a separate validation activity, not a claim of WCAG conformance.

ListBox: single or multi-select

A ListBox bound to create text is single-select and its changed event receives a text value. A ListBox bound to create list is multi-select in Patch Studio App Preview, Standalone Window Web, direct Win32/AppKit/GTK AOT and current token-free Ready/offline Windows, macOS and Linux apps.

create list fruits = ["Banana", "Mango"]
window "Fruit Picker":
  listbox "Apple", "Banana", "Cherry", "Mango" as fruits
when fruits changed:
  change fruits:
    set = value

Selection is transient until the handler executes change. Native GUI IR 1.1 introduced the list-state ABI. Current Native GUI IR 1.3 / payload v13 / runtime v1.4 preserves it while composing TreeView and Slider.

Table / Grid

Table data is written directly in Patch source. Select a Table in the Designer to edit column and cell expressions in Properties, add or remove rows, and add or remove columns. Applying the grid rewrites the visible table/row block and validates row width before accepting it. When the Table has no rows, Properties shows No rows yet and a source-backed Add first row action.

A Table changed event exposes the selected row only as transient list-valued value. Current token-free Ready apps and offline patch link preserve this contract inside payload v13/runtime v1.4.

TreeView

TreeView is hierarchical and source-backed. The Designer can add, select, move, resize, rename and remove the TreeView itself. In Properties, its Tree nodes editor can add roots or children, rename, move, indent/outdent and delete nodes. A filter narrows long node lists while retaining only visible items in keyboard navigation. Each structural action rewrites ordinary visible node source and the editor refuses to leave an empty TreeView.

Selecting a node at runtime produces its root-to-node display path as a transient text-list value. Toolkit selection does not mutate persistent Patch state. Current native consumers use Native GUI IR 1.3 / payload v13 / runtime v1.4 while preserving the TreeView ABI introduced by frozen v12/v1.3.

Tabs pages

Select a Tabs control in the Designer to edit its source-backed page list in Properties. You can add, rename, reorder, duplicate or delete a page within the minimum-page boundary. Reordering/duplication preserves the complete nested control body and remaps ids/handlers where needed.

The selected page exposes its Page controls. Patch Studio can add Text, Button, Input, Checkbox, Radio, ComboBox, ListBox, Table and TreeView directly to that page; Slider Stage 1 is also available there as a source-backed nested control. Nested Table and TreeView receive valid source-backed starter structures and dedicated structural Properties editing.

Click Edit beside a nested Table to open its source-backed row/column structural Properties editor. Click Edit beside a nested TreeView to open its source-backed hierarchy structural Properties editor.

Tabs requires at least two pages. Tabs-inside-Tabs remains fail-closed. Nested page controls use flow layout and page selection remains transient renderer state.

Projects and recovery

Patch Studio autosaves the current versioned project state. The canonical project bundle is v3 and carries bounded multi-file Patch sources, deterministic composition/provenance, project type and build configuration. The Project Tree lets you move between the source-backed files and Forms.

Use Export for a portable .patchproject file, Import to restore one, and Recovery to manage local snapshots. Programmatic sample/Designer changes use the same shared project signals as manual editing.

Build targets

Standalone Web AppSingle HTML output for Console or Window projects, including Slider Stage 1. Desktop appsReady/no-token Windows, macOS and Linux paths plus local and cloud AOT options. Offline compiler downloadsRun, compile, verify and locally link supported Patch apps without opening Studio.

Credentials are only needed by the optional cloud/AOT route and are not persisted by Patch Studio. The normal Ready paths and downloaded offline compiler do not require them.

Ready runtime verification

Before a no-token Windows, macOS or Linux Window build is sealed, Patch Studio verifies the selected runtime template with SHA-256. Pages creates a runtime manifest from the SHA-256 digest recorded on the corresponding GitHub Release asset and independently checks the downloaded bytes. The browser hashes the runtime again before use and stops the build on mismatch.

Current native GUI Ready assets are the three runtime-v1.4 releases. Runtime requests are fresh-first while Studio is online, with a successfully fetched runtime available as offline fallback.

This verifies byte consistency for the runtime-template path. It does not make unsigned development applications Authenticode-signed or Developer ID-notarized.

Offline compiler

After downloading the compiler, use patch check app.patch, patch run app.patch, patch build ... or patch link app.patch --out App. Windows, Linux, Apple Silicon macOS and the Intel macOS kit include the current native Window runtime v1.4. Supported responsive, Table/Grid, list-backed ListBox, Menu, TreeView and Slider apps link locally through payload v13 without a cloud build or account credential.

FreeBSD currently supports Console linking via portable C99 and requires local Node plus cc. Native FreeBSD GUI linking is not yet claimed.

Troubleshooting

The website still looks old or loads incompletely

Patch Studio uses content-addressed web revisions and fresh-first code/runtime requests. Service-worker registration is owned by the early bootstrap only, so later Studio modules cannot replace the active controller. A failed JavaScript, CSS or runtime request is never substituted with index.html; only a real document navigation may use the cached Studio shell.

Every public deployment is also opened in real Headless Chrome, runs the default Window app and must remain JavaScript-responsive through the delayed-freeze window before the deployment status becomes healthy.

A native build stops with an integrity error

Keep integrity verification enabled and reload Studio while online. If the release asset, deployed manifest and fetched runtime do not agree, Patch intentionally refuses to seal the app.

A legacy native build rejects Slider

That is expected for the frozen compatibility line. Native runtime v1.3 is TreeView-capable but Slider-free. Use the current Native GUI IR 1.3 / payload v13 / runtime v1.4 Ready/offline path for native Slider. See the Native compatibility note for the two live contracts.

A TreeView or multi-select ListBox fails with a legacy payload

Use the current Native GUI IR 1.3 / payload v13 / runtime v1.4 path. Frozen older contracts intentionally fail closed rather than silently changing semantics.

A direct Wasm or C99 build rejects a Thing

That is expected. Direct Wasm and portable C99 stay on the numeric Console subset. Thing records are prototype-free own-field product values in the interpreter and Window Web runtime and remain outside the beta.32 Lean claim. The compiler reports this as PATCH2003. Use patch run, Patch Studio or a Window Web build for Thing programs. Use patch doctor to self-check the interpreter plus this fail-closed boundary; on Unix it also compiles and runs the numeric C99 program.

I need support information

Use Copy diagnostics or Report. The Studio report remains local and omits source code while including version, target, compiler status and privacy-redacted errors. Multi-file compiler failures name the owning project file as file:line.
