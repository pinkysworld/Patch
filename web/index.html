One language. One Studio. Many targets.

Programming should feel like making clear changes.

Patch is an experimental general-purpose language where persistent state changes only through explicit change blocks. The beginner-facing language stays small while the runtime records structured semantic changes for history, preview, undo/redo, replay foundations and conflict analysis.

create number count = 0

window "Counter":
  text "Count: {count}"
  button "Add" as add

when add clicked:
  change count:
    add 1

iPhone & iPad

Patch Studio is mobile-first too

Edit and run Patch in Safari, add GUI controls from the Designer, preview applications, inspect Change IR and build portable .patchapp or bootstrap .wasm artifacts locally. To install it like an app on iPhone or iPad, open this site in Safari, tap Share, then Add to Home Screen.

Future Windows .exe, macOS .app and Linux/BSD builds from iOS will be delegated to platform build runners because iOS cannot host those native desktop toolchains itself.

Compiler direction

Portable core, native packaging

Patch source → typed AST → Change IR → WebAssembly / native host

The 0.2 bootstrap Wasm backend already emits a valid WebAssembly module containing the compiled Patch payload for a Patch host. Direct Change IR-to-Wasm execution is the next backend stage. The intended output matrix includes Windows console/GUI apps, macOS CLI/.app, Linux and BSD/Unix apps, web builds and portable .patchapp.

Patch UI

Visual-Basic-style simplicity

Patch UI keeps platform-specific Cocoa/AppKit, Windows and Unix/SDL details behind the runtime. Patch Studio now has a first visual Designer toolbox for adding text, buttons and inputs while keeping the generated source readable. Drag positioning, richer controls and a property inspector remain next-stage work.

Research project

Patch: Change-Oriented Programming with Transparent State Evolution

The research claim is intentionally narrower than “patches are new.” Patch investigates semantic change as the exclusive ordinary mutation primitive of a low-complexity general-purpose language, with one normalized Change IR driving execution, history, inversion, preview, replay foundations, UI state evolution and conflict reasoning.

Current status: a credible high-venue research direction, but not yet a high-venue result. The strongest PL formulation is now State-Change Factorization: every persistent state mutation must factor through a semantic change that is applied as the mutation mechanism itself. A serious submission still requires formalization/mechanization, systematic related-work analysis, a larger compiler/runtime artifact and measured evaluation.
