Offline IDE boundary

The Offline IDE beta is a packaged local Studio, not a second implementation. It embeds the generated public Studio module closure and serves it only on an ephemeral 127.0.0.1 endpoint with a random per-launch path, GET/HEAD-only routing, traversal rejection and restrictive CSP.

Stage 2 remains explicit: the downloaded Offline IDE does not yet expose the standalone native compiler/runtime through a privileged local Build bridge. Use the separate offline compiler when you need host-native patch link output today.

Current native boundary

The current desktop line is Native GUI IR 1.9 / payload v19 / runtime v1.10. It preserves the earlier native layers and adds Current Ready Button/ImageList images plus application/Form Window icons. Native GUI IR 1.7 / payload v17 / runtime v1.8 remains an explicit compatibility line for the Offline Compiler, not the no-flag default. Native GUI IR 1.6 / payload v16 / runtime v1.7 remains the previous PaintBox Stage 1 line, Native GUI IR 1.5 / payload v15 / runtime v1.6 the previous Shape line, Native GUI IR 1.4 / payload v14 / runtime v1.5 the previous Chrome line, and Native GUI IR 1.3 / payload v13 / runtime v1.4 the Slider-capable historical boundary. Versioned contracts are not silently reinterpreted.

PictureBox note: current desktop Picture decoding supports bounded project-resource and data-URI PNG/JPEG images through Win32/WIC, AppKit/NSImage and GTK/GdkPixbuf under native-picture-formats/1.0. This is not a claim of complete portable image-source rendering across every project image type or display property. Native WebP/SVG remain deferred and fail closed.

Current native Window surface

Windows, macOS and Linux offline linking uses the same semantic GUI contract as Patch Studio's token-free Ready path. Toolkit interaction remains transient until Patch source performs an explicit change.

  • Slider: finite numeric changed value inside the declared range; native TRACKBAR/NSSlider/GtkScale.
  • Table/Grid: selected row is a transient text-list event value.
  • List-backed ListBox: selected display strings are a transient text-list event value.
  • Menu: separators, portable shortcuts and source-backed Boolean enabled/checked projections.
  • TreeView: selected root-to-node display path is a transient text-list event value.
  • Responsive layout: source-backed Anchor/Dock metadata reflows native controls without creating hidden Patch state.
  • Panel: Stage 1 native visual grouping. Full Delphi-style child-container semantics are not claimed yet.
  • Timer: native scheduling with Patch ticked events.
  • StatusBar: native/status-style text surface, with platform widget differences kept behind the semantic contract.
  • PictureBox: PNG/JPEG decoding plus the current click path under native-picture-formats/1.0.
  • Shape: rectangle, rounded rectangle, ellipse and line through the native renderers.
  • PaintBox: pure paint rendering with clear, line, rectangle, ellipse, text and bounded PNG/JPEG draw image.
  • ImageList/Button images: named project resources flow through the IR1.8/BIMG layer and native Win32/AppKit/GTK Button consumers.
  • Window/application icons: payload v19/WICO drives native Form icons; Windows embeds the application icon in the PE slot, macOS packages `.icns`, and Linux emits hicolor + `.desktop` metadata.

Native GUI IR 1.5 / payload v15 / runtime v1.6 is the Shape line. Native GUI IR 1.4 / payload v14 / runtime v1.5 is the Chrome line. Native GUI IR 1.3 / payload v13 / runtime v1.4 is the Slider-capable historical line. Native GUI IR 1.2 / payload v12 / runtime v1.3 remains the frozen TreeView line. Older contracts are not redefined: payload v11/runtime v1.2 remains the frozen Menu+list line, v10/v1.1 the persistent-list line, and v9/v1.0 the Table line. Explicit legacy linking fails closed when a program requires a newer feature.

How Patch Studio verifies Ready runtimes

The browser path has a separate integrity gate from the self-contained offline compiler. Pages requires studio-runtime-v0.6 plus the three native runtime-v1.10 releases, reads the SHA-256 digest recorded by GitHub for every runtime template, verifies the downloaded bytes and publishes runtime-manifest.json. Patch Studio then re-hashes the selected runtime with Web Crypto before sealing a Ready app.

Verify a download

Download SHA256SUMS from the same rolling channel and verify the exact bytes before first use or after replacing a rolling-beta download.

# Linux Offline Studio
sha256sum PatchStudio-linux-x64

# macOS Offline Studio
shasum -a 256 PatchStudio-macos-arm64

# Windows Offline Studio
Get-FileHash .\PatchStudio-windows-x64.exe -Algorithm SHA256

# Windows standalone compiler
Get-FileHash .\patch-windows-x64.exe -Algorithm SHA256

SHA-256 verifies release-byte consistency. It is not a replacement for Authenticode, Developer ID/notarization or an independent signing authority. Development artifacts remain explicitly unsigned or ad-hoc signed unless a release states otherwise.

Platform notes

Windows

The Offline Studio beta is a self-contained x64 executable. The compiler links Current Ready Window projects into a native Win32 .exe through runtime v1.10.

macOS Apple Silicon

The standalone compiler produces Current Ready AppKit .app bundles through runtime v1.10. Development builds are ad-hoc signed, not Developer ID notarized.

macOS Intel

The compiler download is a portable tar.gz kit. It includes its own Intel Node runtime and both the Current Ready AppKit runtime v1.10 and legacy runtime v1.8 compatibility underlay. There is not yet a separate macOS Intel Offline Studio beta asset.

Linux

The x64 compiler embeds the GTK3 runtime v1.10 linker. Resulting GUI executables still require compatible normal GTK3/system libraries on the target system.

FreeBSD

FreeBSD currently supports Console linking through the portable C99 backend. Native FreeBSD Window/GUI linking is not claimed yet, and the FreeBSD x64 kit requires local Node 22+ and cc.
