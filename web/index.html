Language & Studio

Working interpreter/compiler frontend, history, undo/redo, preview, why provenance, first GUI/Designer slice, Change Contract and IR views.

Local outputs include Console and Standalone Window Web App HTML builds, direct/bootstrap Wasm where compatible, and portable .patchapp.

Desktop targets

Windows App (.exe), macOS App (.app) and Linux App accept Console or Window Project Type. FreeBSD Console uses Patch's portable C99 backend and the FreeBSD 15.1 base-system compiler.

Guard-aware runtime correspondenceBeta.23 research layer

Independent guard validation

Change IR 0.9 carries guardValidation. A separate raw-source control-flow parser reconstructs the supported GuardTree, normalized guard claims and recipe-parameter vocabulary and compares them with production extraction.

Concrete branch truth

Proof-free RuntimePath and invocation values are checked by PatchGuarded.lean. In the supported safe-integer parameter fragment, branchThen requires the normalized source guard to evaluate true and branchElse requires false. checkedGuardedConcreteRuntimeCannotEscape additionally keeps concrete runtime effects within the declared Change Capability.

This is restricted correspondence, not end-to-end compiler verification.

Window runtime qualityCross-target parity

Executable differential tests

The generated single-file Window runtime is executed in CI and compared with PatchInterpreter. Multi-operation changes see prior operations in the same Change; declared create types and Thing fields are checked consistently.

Conservative event surface

Shared Window preflight rejects duplicate control ids, handlers for missing controls and event forms not wired across all current targets. The portable beta event path is button clicked.

Build formats & boundariesNo silent fallbacks

Direct Wasm + portable C99

Direct Wasm lowers the supported numeric Console subset. Raw direct Wasm uses Patch's small host ABI and is not yet a standalone WASI command. Portable C99 is compile/run tested on Linux, macOS and FreeBSD 15.1.

Window targets

Window Web Apps use the generated browser runtime; Windows/macOS/Linux Window packages use the generated desktop player. They are standalone but are not yet native AppKit, Win32 or GTK widget lowering. FreeBSD Window is not supported yet.
