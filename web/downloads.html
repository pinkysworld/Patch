Verify a download

Download SHA256SUMS into the same folder as the compiler asset. Verify before first use, especially after replacing an older rolling-beta download.

# Linux, or macOS with sha256sum installed
sha256sum -c SHA256SUMS

# macOS built-in tool, compare with the matching SHA256SUMS line
shasum -a 256 patch-macos-arm64

# Windows PowerShell, compare with the matching SHA256SUMS line
Get-FileHash .\patch-windows-x64.exe -Algorithm SHA256

SHA-256 confirms that the downloaded bytes match the published release checksum. It is not a substitute for Authenticode, Developer ID/notarization or a separate independent signing authority. Development artifacts remain explicitly unsigned unless a release states otherwise.

List-backed multi-select ListBox

A ListBox backed by create list is multi-select in Patch Studio App Preview, Standalone Window Web, direct native AOT and current token-free Ready/offline Windows, macOS and Linux Window apps. Its changed event carries a transient list of selected strings.

Selection remains transient UI state until Patch source performs an explicit change. The current native contract is Native GUI IR 1.1 / direct backend 1.2 and sealed payload v10 / runtime v1.1. A text-backed ListBox remains single-select and continues to expose transient text value.

Payload v9/runtime v1.0 remains a frozen Table-capable compatibility line and intentionally does not gain persistent native list state retroactively.

Table / Grid and offline linking

Table/Grid is supported by the language, Designer, Studio App preview, Standalone Web and direct native AOT backend 0.9.

The downloadable Windows, macOS and Linux compiler supports Table through patch link using the current payload v10/runtime v1.1 line. Payload v10 is additive over the prior Table payload: it preserves Table columns, rows, transient row-list events and Anchor/Dock layout while adding persistent text-list state for native multi-select ListBox. CI links and starts responsive, Table and multi-select Window examples on the supported desktop hosts. FreeBSD remains Console-only.

How Patch Studio verifies Ready runtimes

Patch Studio's no-token desktop builds do not blindly package whatever runtime file a browser happens to have cached. The Pages deployment requires the current studio-runtime-v0.6 compatibility/Console release plus all three native runtime-v1.1 releases. It reads the SHA-256 digest recorded by GitHub for every runtime template the browser actually consumes, re-hashes the downloaded bytes and publishes a verified runtime-manifest.json.

The browser loads the integrity gate before the native builder and re-hashes the selected Console, compatibility Window or native GUI runtime with Web Crypto before use. A missing entry or mismatch stops the build. The service worker treats /runtimes/ as fresh-first while online, with a successfully fetched copy retained only as offline fallback.

This verifies byte consistency for the current payload v10/runtime v1.1 Ready path inside the existing GitHub Release and Pages trust path. It is not a replacement for Authenticode or Developer ID/notarization.

Platform notes

Windows

The x64 compiler can link supported Window projects, including Table/Grid and list-backed multi-select ListBox, into a single native Win32 .exe. Responsive controls reflow through the native WM_SIZE path.

macOS Apple Silicon

The Apple Silicon download is one standalone compiler binary. patch link writes supported responsive AppKit .app bundles, including Table/Grid and multi-select ListBox. Development compiler builds are ad-hoc signed, not Developer ID notarized.

macOS Intel

The Intel download is a portable tar.gz kit because Node's SEA path is not currently reliable on macOS x64. It already contains an Intel Node runtime, so no Node installation is required. Console linking creates a portable .app; supported Window apps use AppKit runtime v1.1 with payload v10.

Linux

The x64 compiler links supported Window projects against the embedded GTK3 runtime v1.1. The resulting GUI executable still expects the target system's normal compatible GTK3/system libraries.

FreeBSD

FreeBSD currently supports Console linking through Patch's portable C99 backend. The FreeBSD kit is offline after download but requires a locally installed Node runtime and C compiler. Native FreeBSD Window/GUI linking is not claimed yet.
