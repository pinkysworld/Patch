Stage 2 installed Build boundary

Stage 2 R0.2 is deliberately bounded: on Windows x64, macOS Apple Silicon and Linux x64, --workspace enables a separate authenticated localhost Build bridge. The browser may request only versioned project-snapshot, native-Window-build and opaque-artifact operations. It cannot choose an executable, arbitrary command line, environment map, absolute resource path or output path.

Windows ARM64, Linux ARM64, macOS Intel and the portable Node bundle remain Stage 1/browser-local only until matching host-native compiler/runtime distributions exist.

Current project-v4 binary resources are now transported through the installed-host path. Patch Studio sends its canonical project-v4 bundle, the host independently validates resource paths, decoded sizes and SHA-256 digests, and the existing Offline Compiler performs the normal project-v4 link. Current Picture, ImageList/Button-image and application/Form-icon resources therefore no longer need to fall back merely because the build is local.

Linux desktop package completeness: when application-icon packaging emits the normal hicolor PNG and .desktop sidecars, Offline Studio returns one deterministic <stem>-linux.tar.gz containing those files together with the executable. The archive is created from fixed linker-owned paths without a shell/archive command. Linux builds that have no desktop sidecars retain the direct executable artifact.

Ready runtime verification

Hosted Ready builds use runtime-manifest.json as the browser-side integrity contract. The current desktop runtime releases are native-win32-runtime-v1.10, native-macos-runtime-v1.10 and native-linux-runtime-v1.10. Their published bytes and digests are verified before the generated Studio site exposes them as Current Ready targets.

Current native boundary

The current desktop line is Native GUI IR 1.9 / payload v19 / runtime v1.10. Native GUI IR 1.7 / payload v17 / runtime v1.8 remains an explicit Offline Compiler compatibility line. Native GUI IR 1.6 / payload v16 / runtime v1.7 remains the previous PaintBox line, Native GUI IR 1.5 / payload v15 / runtime v1.6 the previous Shape line, Native GUI IR 1.4 / payload v14 / runtime v1.5 the previous Chrome line, Native GUI IR 1.3 / payload v13 / runtime v1.4 the Slider-capable historical line, and Native GUI IR 1.2 / payload v12 / runtime v1.3 remains the frozen TreeView line. Explicit legacy linking fails closed when a program requires a newer feature.

Use --gui-payload-version 17 only when the explicit runtime-v1.8 compatibility line is required.

PictureBox note: current desktop Picture decoding supports bounded project-resource and data-URI PNG/JPEG images through Win32/WIC, AppKit/NSImage and GTK/GdkPixbuf. This is not a claim of complete portable image-source rendering across every project image type or display property. Native WebP/SVG rendering remains target-specific and fail-closed where unsupported.

Current native Window surface

  • Slider: finite numeric changed values inside the declared range.
  • Table/Grid: transient selected-row values.
  • ListBox: transient selected display values.
  • Menu: separators, shortcuts and source-backed enabled/checked projections.
  • TreeView: selected root-to-node path as a transient text-list value.
  • Panel: Stage 1 native visual grouping.
  • Timer: native scheduling with Patch ticked events.
  • StatusBar: native/status-style text surface.
  • PictureBox: bounded native PNG/JPEG resource decoding.
  • Shape: rectangle, rounded rectangle, ellipse and line.
  • PaintBox: pure paint rendering including bounded image draw operations.
  • ImageList/Button images: named project resources flow through the IR1.8/BIMG layer and native Win32/AppKit/GTK consumers.
  • Window/application icons: payload v19/WICO drives native Form icons and platform application-icon packaging.
