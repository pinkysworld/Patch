Design a Window app

1

Choose Window as the project type or open a Window example.

2

Use the Designer palette to add Text, Button, Input, Checkbox, Radio, Combo, ListBox, Table, TreeView or Tabs controls. Table, TreeView and Tabs expose source-backed structural editors in Properties.

3

Select a control to move it. Drag it to snap nearby edges and centers to visible alignment guides, hold Alt while dragging to bypass snapping, use the arrow keys for 1 px source-backed positioning, hold Shift for 10 px keyboard steps, or edit X/Y/W/H in Properties. Drag its resize grip to change its size.

4

Use Ctrl-click, Cmd-click or Shift-click to add or remove controls from the current selection. The solid control is the primary control. Drag or keyboard-move that primary control to move the selected group together. Alignment commands write the resulting positions back into Patch source.

5

The Properties panel is wider on desktop, can be resized by dragging its left separator, can be hidden with the Properties button and remembers its local width. On narrower screens it moves below the canvas. Properties never stores a second hidden form model.

6

Choose an Anchor or Dock policy in Properties when a control should react to Form resizing. Studio writes that policy visibly into source as a # @layout ... directive.

7

Resize the form itself from the lower-right grip. Forms may grow beyond the visible Designer width; use the Designer scrollbars to reach the rest. The same source-backed Anchor/Dock policy is honored by Standalone Web, direct native AOT, token-free Ready apps and supported offline-linked Window apps on Windows, macOS and Linux.

ListBox: single or multi-select

A ListBox bound to create text is single-select and its changed event receives a text value. A ListBox bound to create list is multi-select in Patch Studio App Preview, Standalone Window Web, direct Win32/AppKit/GTK AOT and current token-free Ready/offline Windows, macOS and Linux apps.

create list fruits = ["Banana", "Mango"]
window "Fruit Picker":
  listbox "Apple", "Banana", "Cherry", "Mango" as fruits
when fruits changed:
  change fruits:
    set = value

Selection is transient until the handler executes change. Native GUI IR 1.1 introduced the list-state ABI. The current Native GUI IR 1.2 / payload v12 / runtime v1.3 line preserves it while adding TreeView.

Table / Grid

Table data is written directly in Patch source. Select a Table in the Designer to edit column and cell expressions in Properties, add or remove rows, and add or remove columns. Applying the grid rewrites the visible table/row block and validates row width before accepting it.

A Table changed event exposes the selected row only as transient list-valued value. Current token-free Ready apps and offline patch link preserve this contract inside payload v12/runtime v1.3.

window "People" as main size 520, 320:
  table "Name", "Role" as people at 24, 64 size 440, 180:
    row "Ada", "Engineer"
    row "Grace", "Scientist"
when people changed:
  show value

TreeView

TreeView is hierarchical and source-backed. The Designer can add, select, move, resize, rename and remove the TreeView itself. In Properties, its Tree nodes editor can add roots or children, rename, move, indent/outdent and delete nodes. Each action rewrites ordinary visible node source and the editor refuses to leave an empty TreeView.

Selecting a node at runtime produces its root-to-node display path as a transient text-list value. Toolkit selection does not mutate persistent Patch state.

create list selected = []
window "Files" as main size 560, 380:
  tree as files at 24, 56 size 300, 240:
    node "src"
      node "compiler.js"
    node "docs"
      node "README.md"
when files changed:
  change selected:
    set = value

Current native support is Native GUI IR 1.2 / payload v12 / runtime v1.3 on Win32, AppKit and GTK3.

Tabs pages

Select a Tabs control in the Designer to edit its source-backed page list in Properties. You can add a page, rename it, move it up or down, or delete it. Reordering preserves the full nested control body. Deleting a page also removes handlers for controls deleted with that page, preventing orphan event handlers.

The selected page also exposes its Page controls. Patch Studio can add Text, Button, Input, Checkbox, Radio, ComboBox, ListBox, Table and TreeView directly to that page, or remove an existing nested control. New named controls receive an id that is unique across top-level and nested controls. Nested Table and TreeView receive small valid source-backed starter structures, and removing either control removes its complete multi-line row/node block rather than leaving orphan source behind.

Table row/column editing and TreeView hierarchy editing for a nested page control remain visible-source operations for now. The dedicated top-level Table/TreeView structural Properties editors are unchanged. Tabs cannot be nested inside Tabs, and the nested editor refuses to leave a page empty.

window "Settings":
  tabs as settings:
    tab "General":
      text "General"
      table "Name", "Value" as preferences:
        row "Theme", "System"
    tab "Advanced":
      tree as sections:
        node "Security"
          node "Keys"

Tabs requires at least two pages, so the editor will not delete below that limit. Nested page controls use flow layout. Page selection remains transient renderer state and does not become persistent Patch state. Current Ready/offline builds use Native GUI IR 1.2 / payload v12 / runtime v1.3.

Projects and recovery

Patch Studio autosaves the current versioned project state. The canonical project bundle is v3 and carries bounded multi-file Patch sources, deterministic composition/provenance, project type and build configuration. The Project Tree lets you move between the source-backed files and Forms.

Use Export for a portable .patchproject file, Import to restore one, and Recovery to manage local snapshots. Programmatic sample/Designer changes use the same shared project signals as manual editing.

Build targets

Standalone Web AppSingle HTML output for Console or Window projects. Desktop appsReady/no-token Windows, macOS and Linux paths plus local and cloud AOT build options. Offline compiler downloadsRun, compile, verify and locally link supported Patch apps without opening Studio.

Credentials are only needed by the optional cloud/AOT route and are not persisted by Patch Studio. The normal Ready paths and downloaded offline compiler do not require them.

Ready runtime verification

Before a no-token Windows, macOS or Linux Window build is sealed, Patch Studio verifies the selected runtime template with SHA-256. Pages creates a runtime manifest from the SHA-256 digest recorded on the corresponding GitHub Release asset and independently checks the downloaded bytes. The browser hashes the runtime again before use and stops the build on mismatch.

Current native GUI Ready assets are the three runtime-v1.3 releases. Runtime requests are fresh-first while Studio is online, with a successfully fetched runtime available as offline fallback.

This verifies byte consistency for the runtime-template path. It does not make unsigned development applications Authenticode-signed or Developer ID-notarized.

Offline compiler

After downloading the compiler, use patch check app.patch, patch run app.patch, patch build ... or patch link app.patch --out App. Windows, Linux, Apple Silicon macOS and the Intel macOS kit include the current native Window runtime v1.3. Supported responsive, Table/Grid, list-backed ListBox, Menu and TreeView apps link locally through payload v12 without a cloud build or account credential.

FreeBSD currently supports Console linking via portable C99 and requires local Node plus cc. Native FreeBSD GUI linking is not yet claimed.

Troubleshooting

The website still looks old

Patch Studio uses content-addressed web revisions and fresh-first code/runtime requests. Reload once while online, or close and reopen an installed PWA.

A native build stops with an integrity error

Keep integrity verification enabled and reload Studio while online. If the release asset, deployed manifest and fetched runtime do not agree, Patch intentionally refuses to seal the app.

A TreeView or multi-select ListBox fails with a legacy payload

Use the current Native GUI IR 1.2 / payload v12 / runtime v1.3 path. Frozen older contracts intentionally fail closed rather than silently changing semantics.

I need support information

Use Copy diagnostics or Report. The Studio report remains local and omits source code while including version, target, compiler status and privacy-redacted errors.
