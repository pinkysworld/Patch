Language & Studio

Working interpreter/compiler front end, history, undo/redo, preview, why provenance, first GUI/Designer slice, Change Contract and IR views.

Local outputs include Console and Standalone Window Web App HTML builds, direct/bootstrap Wasm where compatible, and portable .patchapp.

Desktop targets

Windows App (.exe), macOS App (.app) and Linux App accept Console or Window Project Type. FreeBSD Console uses Patch's portable C99 backend and the FreeBSD 15.1 base-system compiler.

Window build fixBeta.21

Correct desktop preflight

The compiler represents a Patch Window as normalized code: "WINDOW". Studio now checks that actual IR representation before dispatching a Windows/macOS/Linux Window build, fixing the older false “does not define a Patch window” rejection.

Separate Window Web backend

Window Web projects no longer enter the Console-only Direct Wasm backend. They build as a self-contained HTML application with Patch's generated browser Window runtime, controls and events. Direct WebAssembly remains explicitly Console-only.

Research & verificationSource + runtime correspondence

State-Change Factorization

Semantic Change Contracts

Patch infers operation- and magnitude-aware Change Signatures and constrains them with Change Capabilities. The Lean core covers factorization, Change Signature Soundness, policy containment, source/evidence correspondence and integer range-analysis soundness for explicitly modeled fragments.

Independent raw-source validation reconstructs supported Source core/range claims without importing the production parser before static certification.

Beta.21

Runtime → Lean correspondence

patch runtime-certify executes direct Wasm and emits proof-free concrete effects plus an untrusted RuntimePath. Lean validates branchThen/branchElse, exact repeatSucc/repeatZero structure and repeated protected invocations before deriving an actual formal SourceExecutes trace.

This is restricted runtime correspondence, not end-to-end compiler verification.

Build formats & boundariesNo silent fallbacks

Console Direct Wasm + portable C99

Direct Wasm lowers the supported numeric Console subset to WebAssembly instructions. Raw direct Wasm uses Patch's small host ABI and is not yet a standalone WASI command. Portable C99 is compile/run tested on Linux, macOS and FreeBSD 15.1.

Window targets

Web Window apps use the generated browser Window runtime. Desktop Window projects use the current generated desktop player on Windows/macOS/Linux. These are standalone but beta.21 does not claim native AppKit, Win32 or GTK widget lowering. FreeBSD Window packaging is not yet supported.
