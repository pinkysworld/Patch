Abstract

General-purpose languages usually expose persistent mutation through assignment or data-structure-specific updates, while auditing, undo, provenance, replay and policy enforcement reconstruct additional semantic structure around those writes. Patch explores the opposite factorization: ordinary post-creation persistent mutation is represented and committed through a structured semantic Change. A programmer writes change score: add 1; ordinary reassignment is not an alternative modeled persistent-update route.

Patch derives Semantic Change Signatures and optional Change Capabilities from the same mandatory mutation representation. These contracts distinguish target, semantic operation and, for a supported numeric fragment, magnitude. A Lean 4 development proves factorization, mutation transparency, signature and policy properties, integer range soundness, finite ranked call composition, exact safe-integer call binding, guarded structured traces and finite transitive exact call-tree refinement for explicit fragments.

Beta 32 reconstructs concrete invocation frames independently of backend call markers, including repeated identical calls and mixed-guard repeated identities. Generated certificates check each frame binding against the beta 30 exact call tree and let Lean re-evaluate frame-selected observed semantic effects. No controlled performance result, external plugin-ecosystem result, complete sandboxing result, or end-to-end compiler-verification result is claimed.

Candidate contribution

Patch factors ordinary post-creation persistent mutation through a structured semantic Change, and derives operation- and magnitude-aware summaries and authority from that same mandatory mutation substrate.

This is an architectural conjunction, not a unique-expressibility claim. Plaid, effect systems, graded and dependent effects, capabilities, typestate, HTT/F* and patch theory already occupy neighbouring points. The remaining question is whether forcing ordinary modeled persistent mutation through one semantic delta is useful.

Contributions. The working manuscript packages (1) factorization and transparency for the modeled mutation machine, (2) signatures/capabilities with Lean range and policy soundness on explicit fragments, (3) the call-assurance stack through beta.32 mixed-guard invocation frames, (4) independent JavaScript source/range, guard and call-site identity checks that are not a verified parser, and (5) ablation, two-domain corpus, measurement protocol and reproducibility packaging with no performance result claimed.

Mixed-guard invocation frames

Beta 32 reconstructs concrete invocation frames independently of backend call markers. The mixed-guard regression executes caller(1), caller(4), caller(1) through caller → outer → middle → leaf. Independent validation reconstructs twelve invocation frames and six supported transitive correspondences. The three outer witnesses keep distinct dynamic identities with effects coins +4, score +5, coins +4.

create number score = 0
create number coins = 0

make leaf(amount number 1..5):
  if amount >= 3:
    change score:
      add amount
  else:
    change coins:
      add amount * 2

make caller(seed number 0..4):
  do outer(seed)

Empirical boundary

The measurement pipeline is implemented and regression-tested, but this manuscript reports no controlled paper-quality timing dataset yet.   11. Process-isolated controlled-measurement protocol and commit-bound reproducibility bundle.

Limitations

Construct validity. Lean covers explicit fragments. Independent source/range, guard and call-site validators are JavaScript, not verified parsers. Runtime correspondence checks accepted reconstructed evidence; it does not prove capture completeness, lowering or the WebAssembly engine. The coarse baseline is an internal target-only ablation.

Internal validity. No controlled paper-quality timing dataset exists yet, so there is no measured overhead result. Hosted-CI timing cannot be relabelled. Security cases are deterministic artifact matrices, not a sampled vulnerability corpus.

External validity. Checkout/loyalty and usage/quota are not a complete plugin sandbox and not evidence about a third-party plugin ecosystem. GUI, Things and native Window runtimes stay outside beta.32. The candidate novelty is a conjunction of architectural choices and still requires expert/venue scrutiny.

Still open

These remaining research gates need data or external participation. They are not missing product controls, and they do not widen the beta.32 claim. This page still reports no controlled paper-quality timing dataset yet.

  • fixed-machine controlled overhead/scaling measurements, then review-gated analysis and hand sync into the LaTeX manuscript;
  • a genuine external/third-party extension or integration study;
  • expert/venue feedback on whether the architectural conjunction is distinct and useful;
  • further reductions of parser/lowering/runtime trust that strengthen the claim without turning it into an end-to-end compiler theorem.
