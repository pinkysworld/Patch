Language & Studio

Working interpreter/compiler front end, history, undo/redo, preview, why provenance, first GUI/Designer slice, Change Contract and IR views.

Local outputs include Standalone Web App, direct WebAssembly, bootstrap Wasm and portable .patchapp.

Desktop targets

Windows, macOS and Linux support Console and Window/GUI packages. The selected Project Type chooses the package. FreeBSD Console uses Patch's portable C99 backend and FreeBSD 15.1 base-system compiler.

Research & verificationThree independent boundaries

State-Change Factorization

Semantic Change Contracts

Patch infers operation- and magnitude-aware Change Signatures and can constrain them with Change Capabilities. The Lean formal core covers factorization, Change Signature Soundness, policy containment and integer range-analysis soundness for explicitly modeled fragments.

Beta.19

Independent raw-source validation

A small validator re-parses the exact Patch source without importing parser.js or consuming the production AST. It independently reconstructs formal Source core structure and range claims, then compares them with the production AST-derived artifact.

patch certify requires this comparison for supported protected recipes before emitting the Lean-checkable certificate. This is translation validation, not a parser-correctness theorem.

Build formats & boundariesNo silent fallbacks

Direct Wasm + portable C99

Direct Wasm lowers the supported numeric Console subset to WebAssembly instructions. Raw direct Wasm uses Patch's small host ABI and is not yet a standalone WASI command. Portable C99 lowers the same conservative subset and is compile/run tested on Linux, macOS and FreeBSD 15.1.

Window packages

Window projects are standalone GUI packages on Windows, macOS and Linux through the current desktop player. Beta.19 does not claim native AppKit, Win32 or GTK widget lowering yet. FreeBSD Window packaging is not yet supported.

Runtime validationEvidence, not overclaiming

Independent transition model

An independent validator reconstructs expected Change-IR transitions and compares target/before/after ordering with observed direct-Wasm execution.

Semantic effects

Concrete increase/decrease/set/clear effects and magnitudes are reconstructed separately and checked against static Change Signatures and protected Change Capabilities. This is translation/runtime validation evidence, not complete compiler verification.
