Semantic security

Permission to change is more precise than permission to write

A normal write permission says code may modify a value. Patch can say that a recipe may only perform a particular semantic change, for example player.score may increase up to 10. A replacement with set score = 999 is a different semantic operation and is rejected.

With ranged parameters, the production analyzer can reason about bounded dynamic changes instead of rejecting them merely because an amount is a variable.

Verified checker

Production code emits evidence; Lean checks the formal policy

patch certify protected.patch emits a Lean certificate containing the bridge-produced formal statement, policy, source SHA-256 and a machine-checkable protectedness theorem.

PatchChecker.lean proves that a successful executable policy check implies the relational policy judgment and therefore runtime policy containment for every modeled execution of that formal statement.

Compiler ↔ formal model

The remaining trust boundary is explicit

The compiler independently reconstructs a Lean-like control-flow signature from the real Patch AST for the currently supported subset and compares it with the production Change Signature. A supported mismatch is a compiler error.

The JavaScript source-to-formal translation is not yet proved correct. Unsupported constructs are listed rather than silently called verified. patch formal program.patch shows current coverage.

Causal provenance

Ask Patch why a value or condition exists

why score explains recorded semantic changes behind the current value. why score > 100 replays history and identifies the first recorded transition that made the condition true when one can be isolated.

GUI-driven changes can retain provenance such as event bonus clicked → recipe reward → change score.

Research project

Patch: State-Change Factorization and Semantic Change Contracts

The research claim is intentionally narrower than “patches are new.” Patch investigates semantic change as the exclusive ordinary mutation mechanism of a low-complexity language. Operation- and magnitude-aware contracts are derived from that mandatory representation.

Current status: the formal core has machine-checked signature and policy containment; a production bridge translation-validates a conservative subset; and beta 6 adds a Lean-verified checker for generated semantic-policy evidence. The next major obligation is source/Change-IR-to-formal correspondence, followed by interval-analyzer soundness and measured security case studies.
