Patch programming language

Small syntax. Build an app.

Patch is an experimental language where existing persistent state changes through semantic change operations rather than ordinary reassignment. Patch Studio can build locally for the web and send the source currently in the editor to GitHub Actions for Windows, macOS and Linux desktop builds.

Cross-platform desktop builds

Choose Windows / macOS / Linux desktop in Studio and press Build. Studio sends the current unsaved Patch source to the repository's GitHub Actions builder, monitors the run and exposes the resulting artifacts.

Console projects use the direct Patch Wasm native host. Window projects are packaged as standalone desktop GUI applications. The GitHub token is kept only in the current browser tab and is not saved by Patch Studio.

Research project

State-Change Factorization

The central research claim is deliberately narrow: ordinary post-creation persistent mutation must execute through a semantic change. Patch does not claim that patches, undo, effects or first-class state change are individually new.

Change Capabilities constrain semantic operation and magnitude, for example allowing a recipe to increase a value only up to a declared bound.

Formal assurance

Lean-checked core

The formal project covers State-Change Factorization, Mutation Transparency, Change Signature Soundness, policy containment and integer range-analysis soundness for explicitly modeled fragments.

The Verified checker, Source core and PatchSource modules keep source operations and semantic evidence distinct. patch certify emits Lean-checkable certificates for supported protected programs.
