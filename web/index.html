Direct Wasm and portable C99

The direct backend lowers the supported numeric subset to WebAssembly instructions. The raw .direct.wasm currently imports Patch's small host ABI, so it is not yet a standalone WASI command.

The new C99 backend lowers the same conservative Console subset from Change IR into portable C. It has been compiled and run on Linux, macOS and FreeBSD 15.1. This does not silently claim OpenBSD or NetBSD support before they are tested.

Window packages are standalone

Current Window projects can be packaged as desktop GUI applications for Windows, macOS and Linux. They run the Patch Window model inside a generated desktop player; beta.18 does not claim native AppKit, Win32 or GTK widget lowering yet.

FreeBSD currently supports Console projects only. A portable Unix GUI backend remains a roadmap item.

Research & verificationTechnical view

Research project

State-Change Factorization

The central claim is deliberately narrow: ordinary post-creation persistent mutation must execute through a semantic change. Patch does not claim that patches, undo, effects or first-class state change are individually new.

Change Capabilities constrain semantic operation and magnitude, for example allowing a recipe to increase a value only up to a declared bound.

Formal assurance

Lean-checked core

The formal project covers State-Change Factorization, Mutation Transparency, Change Signature Soundness, policy containment and integer range-analysis soundness for explicitly modeled fragments.

The Verified checker and Source core keep producer claims separate from Lean validation. patch certify emits Lean-checkable certificates for supported protected programs.

Runtime validationCompiler evidence, not overclaiming

Independent transition model

For the direct numeric Wasm backend, an independent validator reconstructs expected Change-IR transitions instead of using the Wasm lowerer or production interpreter as its sole oracle.

Semantic effect checks

The validator reconstructs concrete increase/decrease/set/clear effects and checks them against static Change Signatures and protected Change Capabilities. This is translation/runtime validation evidence, not a theorem that the complete compiler is verified.
