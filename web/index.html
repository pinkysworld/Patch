One language. One Studio. Many targets.

Programming should feel like making clear changes.

Patch is an experimental general-purpose language where persistent state changes only through explicit change blocks. The beginner-facing language stays small while the runtime records structured semantic changes for history, preview, undo/redo, replay foundations and conflict analysis.

create number count = 0

window "Counter":
  text "Count: {count}"
  button "Add" as add

when add clicked:
  change count:
    add 1

iPhone & iPad

Patch Studio is mobile-first too

Edit and run Patch in Safari, preview GUI programs, inspect Change IR and build portable .patchapp bundles locally. To install it like an app on iPhone or iPad, open this site in Safari, tap Share, then Add to Home Screen.

Future Windows .exe, macOS .app and Linux/BSD builds from iOS will be delegated to platform build runners because iOS cannot host those native desktop toolchains itself.

Compiler direction

Portable core, native packaging

Patch source → typed AST → Change IR → WebAssembly / native host

The intended output matrix includes Windows console and GUI applications, macOS command-line tools and .app bundles, Linux and BSD/Unix applications, web builds and the portable .patchapp format. A C99 backend remains a planned portability escape hatch for unusual Unix systems.

Patch UI

Visual-Basic-style simplicity

Patch UI is designed so programmers say window, text, button and when ... clicked, while platform-specific Cocoa/AppKit, Windows and Unix/SDL details stay behind the runtime. A drag-and-drop form designer and property editor are next major Studio milestones.

Research project

Patch: Change-Oriented Programming with Transparent State Evolution

The research claim is intentionally narrower than “patches are new.” Patch investigates what happens when semantic change is the exclusive ordinary mutation primitive of a deliberately low-complexity general-purpose language, and when one normalized change representation drives execution, history, inversion, preview, replay foundations, UI state evolution and conflict reasoning.

Current status: promising research artifact, not yet a high-venue result. The path to a strong PL paper requires a systematic related-work review, formalized or machine-checked properties, a larger compiler/runtime artifact, benchmark evaluation and preferably a controlled novice-comprehension study.
